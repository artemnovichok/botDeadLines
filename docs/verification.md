## Воспроизведение

Обновление ограничения расходов и обратной связи, 20 октября 2026:
**302 passed, 6 skipped** (39,77 с), Ruff и strict mypy прошли. Дополнительные
10 проверок jobs/лимитов прошли после уточнения текста ошибок.
Добавлены мягкие пределы запуска (300 с между порциями и 100000 usage-токенов
перед следующей порцией истории), статус `partial` со сводкой, уведомления о
прогрессе каждые 120 с и `/stop_sync`. Проверены продолжение с checkpoint,
отсутствие лишнего оплачиваемого вызова после лимита и код CLI 4 при частичном результате.
SDK не повторяет запросы после таймаута/обрыва/5xx; только явные отказы 429 имеют
ограниченные повторы. Формат ответа по-прежнему может исправляться ограниченное число раз.
Для GPT-6 явно запрашивается low; явный отказ шлюза от reasoning_effort имеет
однократный fallback. Реальное качество и задержка этой настройки у провайдера
платным тестом не проверялись.

Полные источники теперь выбираются по текущему чату, предмету/названию, ссылкам,
исправлениям и конфликтам; каталог событий остаётся общим. На read-only снимке
рабочих данных (22 события) пример сократился с 32 до 6 полных источников и
с 19170 до 12127 оценочных входных токенов. Тексты в БД сохранены полностью.
Пользовательский запуск сам завершился APITimeoutError, сохранив 986 сообщений
и 14 новых событий. При обновлении этот запуск не прерывался и заново не запускался.
Копия БД: `data/backups/before-bounded-analysis-20261020.sqlite`.

Обновление обработки долгого анализа, 20 октября 2026: **289 passed, 6 skipped**
(40,11 с), Ruff и strict mypy без ошибок. На рабочих метриках подтверждён обрыв
ровно через 600,02 с после сохранения 900 сообщений и 5 событий.
`SYNC_TIMEOUT_SECONDS` теперь ограничивает отсутствие прогресса; успешный commit
порции, включая рекурсивное деление и обновление источников, продлевает ожидание.
Учитывается также прогресс обработки сохранённых исправлений. Регрессии проверяют
общую длительность выше лимита, настоящее зависание, сохранность checkpoint,
продолжение без повторной обработки и актуальную длительность в `/status`.
Перед обновлением создана и проверена SQLite-копия
`data/backups/before-idle-timeout-20261020.sqlite`.

Последнее обновление 20 октября 2026: **283 passed, 6 skipped** (33,03 с),
Ruff и strict mypy (48 модулей) без замечаний. Проверены пропуск старой истории
с checkpoint в редком чате, исключение прошедшей неподтверждённой даты и сохранение
досдачи, однократный запрос группы, ввод после потери FSM, изоляция профилей,
смена группы во время анализа и BPE для трёх вариантов имени GPT-6.
Оценка пустого запроса с настроенной `gpt-6-luna` теперь 6051 вместо прежних
22088 при бюджете 30000 (текущий промпт содержит и правила групп).

Рабочий Mac Docker-контейнер пересобран и обновлён; статус `healthy`,
`check-config` и `alembic check` прошли. Миграция `f106_study_group` применена
после онлайн-копии `data/backups/before-study-group-20261020.sqlite`.
Число профилей, подключений, чатов, событий и источников совпало с копией.
Реальный повторный анализ чатов, платные запросы ИИ и проверка качества
распределения групп живой моделью в этом обновлении не запускались.

```sh
uv sync --frozen
uv run ruff check .
uv run ruff format --check .
uv run mypy src
uv run pytest -q
uv run python -m compileall -q src
uv run python scripts/verify_deployment.py --pytest-postgres
```

Последняя команда требует работающий Docker daemon. Она создаёт временный Compose-проект,
случайный пароль тестового PostgreSQL и отдельные volumes. API-ключи не передаются,
пользовательский `.env` не используется. После проверки удаляются только эти временные
контейнеры и volumes. Повторная проверка готового образа:

```sh
uv run python scripts/verify_deployment.py --skip-build --pytest-postgres
```

Для настоящего LLM экспортируйте LOWROUTER_API_KEY безопасным способом, настройте
модель и выполните `RUN_LLM_INTEGRATION=1 uv run pytest -m integration -q`.
Это платные обращения, в итоговой проверке они не выполнялись.

## Что покрыто

- Полный сценарий `tests/test_end_to_end.py`: start → одобрение веб-входа → Telegram
  с мок-кодом → выбор чата → анализ → дедлайн → новый перенос → конфликт → выбор → сводка
  → повтор без дублей → пропущенный ночной цикл после восстановления → полное удаление.
- `tests/test_operations.py`: read-only dry-run без изменения любой основной таблицы,
  восстановление ответа LLM после сбоя до checkpoint, независимые параллельные сервисы,
  сохранение живого CLI при старте сервера, деление контекста без потери хвоста,
  ошибки пользователей, удаление владельца, межпроцессная блокировка с SIGKILL,
  общие слоты LLM между независимыми клиентами.
- `tests/test_cli.py`: справка всех команд, взаимоисключающие режимы и валидация ID,
  согласование новых/старых переменных окружения, проверка схемы, диагностический LLM-вызов,
  настоящий внутренний цикл с мок-API, send-summary без LLM, код 4 при частичном успехе,
  безопасная диагностика HTTPS без раскрытия секрета.
- `tests/test_postgres.py`: реальная PostgreSQL с отдельными БД для миграций,
  read-only snapshot, параллельного анализа и межсоединительных блокировок/лимитов.
- `tests/test_backup.py`: согласованная копия и восстановление SQLite, права 600,
  запрет неявной перезаписи.
- `tests/test_process.py`: настоящий HTTP-процесс без ключей, healthcheck, SIGTERM;
  авария мок-polling приводит к штатному завершению с кодом 5 для рестарта.
- Прежние тесты сохранены и пройдены: UTC/пояса/DST, четыре раздела сводки, досдачи,
  длинная HTML-сводка, конфликты 3+, пользовательские правки/undo/completion, версии и владельцы,
  SQL-транзакции, откат SAVEPOINT, шифрование сессий, QR/телефон/2FA, подмена аккаунта,
  Origin/CSRF/HTTPS, временные сбои, заблокированный бот, source refresh и retention.

## Ручная проверка перед эксплуатацией

Реальные Telegram-вход, доставка пользователю, действующий публичный TLS-сертификат,
DNS, имя/доступность модели LowRouter и семантическое качество на настоящих чатах
требуют проверки владельцем установки. Linux-контейнеры проверены локально; публичный VPS
в этой среде не разворачивался. Рабочая БД остаётся на своей прежней версии до явного
backup и запуска миграций оператором. Подробности и ограничения — в
[DEVELOPMENT_REPORT.md](../DEVELOPMENT_REPORT.md) и [README.md](../README.md).

На Mac теперь достаточно открыть `start.command`: он запускает Docker Desktop и локальный
профиль HTTPS на 127.0.0.1:8443. Вводные ключи берутся из существующего `.env`, а адрес HTTPS
переопределяется только в контейнере. Первое добавление ограниченного SSL/localhost-доверия
к сертификату в пользовательскую связку ключей выполняется при запуске скрипта пользователем;
это системное подтверждение не выполнялось в автоматической проверке. Реальный бот с
пользовательскими ключами также не запускался. Тестовые контейнеры после проверки удалены.
